TASK MANAGER WEB APP - COMPLETE DATABASE SETUP GUIDE

==================================================
1. DATABASE OVERVIEW
==================================================

The Task Manager Web App uses:

- Flask
- Flask-SQLAlchemy
- SQLite for local development
- SQLAlchemy ORM

The database configuration is located in:

app/__init__.py

The default local database is:

tasks.db

The application can also use another database by setting:

DATABASE_URL

If DATABASE_URL is not provided, the application uses the default SQLite database.

IMPORTANT:
Do NOT commit the local SQLite database file to GitHub.


==================================================
2. PROJECT DATABASE STRUCTURE
==================================================

The main database models are defined in:

app/models.py

The project contains three main models:

1. User
2. Category
3. Task


--------------------------------------------------
USER
--------------------------------------------------

The User table stores registered users.

Main fields:

- id
- username
- email
- password_hash

A user can have multiple tasks.

A user can also have multiple categories.

Passwords are stored as password hashes and should NOT be stored as plain text.


--------------------------------------------------
CATEGORY
--------------------------------------------------

The Category table stores task categories belonging to users.

Main fields:

- id
- name
- user_id

Each category belongs to a user.

Categories can be used to organize tasks.


--------------------------------------------------
TASK
--------------------------------------------------

The Task table stores tasks created by users.

Main fields:

- id
- title
- description
- status
- priority
- due_date
- created_at
- user_id
- category_id

Task status values include:

- pending
- in_progress
- done

Task priority values include:

- low
- medium
- high

Each task belongs to a user.

A task can optionally belong to a category.


==================================================
3. DATABASE RELATIONSHIPS
==================================================

The database relationships are:

User
 |
 +---- Categories
 |
 +---- Tasks

Category
 |
 +---- Tasks

In simple terms:

One User -> Many Categories

One User -> Many Tasks

One Category -> Many Tasks

Database configuration is handled in:

Example:

DATABASE_URL=sqlite:///tasks.db

If DATABASE_URL is not configured, the application uses the project's default SQLite database.

6. REQUIREMENTS INSTALLATION
==================================================

First create a virtual environment:

python -m venv venv

.\venv\Scripts\Activate.ps1

Install the project dependencies:

pip install -r requirements.txt


==================================================
7. CREATE / INITIALIZE DATABASE
==================================================

Start the Flask application:

python run.py

The application initializes the database using:

db.create_all()

The required tables are created from the SQLAlchemy models.

The database is normally created automatically when the application starts.

The seed script may create:

- Demo users
- Demo categories
- Sample tasks

IMPORTANT:

Therefore, use:

python seed.py

Do NOT run the seed script on a database containing data that you want to keep.

==================================================
10. AUTHENTICATION AND DATABASE
==================================================

Authentication uses the User database table.

The authentication API is located in:

app/routes/auth.py

Main authentication operations include:

POST /api/auth/register

POST /api/auth/login

POST /api/auth/logout

GET /api/auth/me

User passwords are stored using password hashing.

Authenticated API requests use the currently logged-in user.

Users should only be able to access their own:

- Tasks
- Categories
- Statistics


==================================================
11. TASK DATABASE OPERATIONS
==================================================

Task API routes are located in:

app/routes/tasks.py

Tasks are associated with the logged-in user through:

user_id

The application supports operations such as:

GET /api/tasks

POST /api/tasks

PUT /api/tasks/<task_id>

DELETE /api/tasks/<task_id>

Task records can contain:

- Title
- Description
- Status
- Priority
- Due date
- Category
- User ownership


==================================================
12. CATEGORY DATABASE OPERATIONS
==================================================

Category API routes are located in:

app/routes/categories.py

Categories are associated with the logged-in user through:

user_id

The application supports category operations such as:

GET /api/categories

POST /api/categories

DELETE /api/categories/<cat_id>

Categories help organize tasks.


==================================================
13. STATISTICS
==================================================

Statistics API routes are located in:

app/routes/stats.py

Statistics are calculated for the currently authenticated user.

The statistics API can provide:

- Total tasks
- Pending tasks
- Completed tasks
- Overdue tasks
- Tasks grouped by priority

The statistics are calculated from the Task table.


==================================================
14. DATABASE INDEX
==================================================

The Task model contains an index for frequently used user/task queries.

The index uses:

user_id
status
due_date

This can improve query performance for operations involving:

- User-specific tasks
- Task status
- Due dates

==================================================
16. CLEAN DATABASE RESET
==================================================

If the local database needs to be recreated during development:

1. Stop the Flask server.

2. Remove the local SQLite database file if appropriate.

3. Start the application again:

python run.py

The application will recreate the required database tables using the SQLAlchemy models.

WARNING:

Only delete the local database when you are sure that you do not need the existing local data.
